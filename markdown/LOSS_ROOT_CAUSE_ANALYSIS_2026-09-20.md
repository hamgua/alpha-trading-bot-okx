## 一、量化结论：这是一个结构性负期望系统

| 指标 | 实测值 | 说明 |
|---|---|---|
| 开仓次数 | 61（多 35 / 空 26） | 30 天，约每天 2 笔 |
| 确认平仓 | 27 笔：盈 3 / 亏 24 | 胜率 **11.1%** |
| 绩效追踪平仓 | 15 笔：盈 5 / 亏 10 / 平 1 | 胜率 **33.3%** |
| 平均盈利 | **+0.387%**（价格） | 毛 |
| 平均亏损 | **-0.624%**（价格） | 毛 |
| 毛盈亏比 | **0.62** | 亏得比赚得多 |
| 往返 taker 手续费 | **0.10%**（名义） | 0.05%×2 |
| 净盈利/笔 | **+0.287%** | 0.387% − 0.10% |
| 净亏损/笔 | **−0.724%** | 0.624% + 0.10% |
| **净盈亏比** | **0.396** | 扣费后进一步恶化 |
| **盈亏平衡所需胜率** | **71.6%** | 在 0.396 净盈亏比下 |
| **实测胜率** | **11%~33%** | 远低于盈亏平衡线 |

**每笔期望值（按 33% 胜率）≈ −0.387% 名义**，即每开一单平均亏掉仓位名义价值的 0.39%。
这不是运气或某个坏行情段——**只要"净盈亏比 0.4 + 胜率 11~33%"这个结构不变，无论信号多好都必然持续亏损。**

分方向确认平仓：多单 n=14 净 −8.60%，空单 n=13 净 −5.21%。同期 BTC 从 $72.5k 涨到 $80.4k（+10%），
多空两边都在流血，说明问题不在"看错方向"，而在**出场结构（赚小亏大）+ 逆势开空**。

## 二、七大根因（均有日志/代码证据）

### R1（首要）：止盈距离被系统性砍半 → R/R 结构性倒挂
- 代码 `adaptive_bot._adjust_full_amount_take_profit_price` 在分批止盈数量低于最小张数时
  退回全仓止盈，并把止盈目标按 `take_profit_partial_ratio`(0.5) **拉近一半**。
- 最小张数仓位（0.01 张）100% 走该分支 → **30 天日志 57/57 笔**止盈距离被压缩
  （原始自适应止盈均值 0.729% → 实际约 0.36%）。
- 而止损距离平均 0.623%（规则引擎 0.5%~1.5% 波动带）。
- **结果：赚 0.36% 止盈，亏 0.62% 止损，盈亏比 0.62，扣费后 0.4。** 这是持续亏损的第一根因。

### R2：追踪止损在"手续费级浮盈"就落袋
- 追踪距离 0.2%（`STOP_LOSS_PROFIT_PERCENT=0.002`），旧收紧门槛仅 0.1%（`min_profit_to_tighten=0.001`）。
- 价格只要浮盈 0.1% 就开始把止损上移 0.2%，最终"盈利"常在 0.1~0.3% 之间被扫出——
  **扣掉 0.1% 往返费后接近 0**。日志中 15 笔结算 5 笔盈利均值仅 +0.37%（≈3 倍往返费）。

### R3：名义价值按"张数当 BTC 数量"计算，高估 100 倍
- `notional = amount × price`，对 BTC-USDT-SWAP（1 张 = 0.01 BTC）高估 100×。
- 日志实证：0.01 张被记为 `notional=745.79`，实际仅 ≈$7.5。
- 后果：`TAKE_PROFIT_MIN_NOTIONAL=50` 等名义金额门禁**全部失真**（以为仓位 $745，实际 $7.5）。

### R4：开仓张数硬编码最小值，仓位决策是死代码
- `_execute_trade` 中 `max_amount=0.01` 硬编码，`suggested_position`（0.05~0.1 的容量比例）
  被直接当张数再 `min(0.01)` → **仓位恒为最小张数**，账户余额/杠杆/权益从未参与决策。
- 实际每单名义仅 ≈$7.5，即使策略是正的，绝对收益也可忽略；而手续费占比被放大。

### R5：平仓审计只查止损单，止盈触发永远"推断"
- `position_close_audit` 只查**止损单** algo 历史。止盈单触发平仓时止损单无成交记录
  → 49%（26/53）的平仓只能"推断"，且**按止损价估算 PnL**（止盈盈利被记成止损亏损）。
- 学习闭环（adaptive_weight_optimizer / performance_tracker）样本系统性失真。

### R6：止损重试塌缩到 0.1%/1USDT → 裸仓化
- `adaptive_stop_loss` 重试时一律把止损价重算为 `current_price ± max(0.1%, 1USDT)`。
- 对 BTC 这约 0.0013%~0.1%，**比 15 分钟周期噪音还窄**。日志中出现 +0.015% 的"止损"
  （2026-09-04 空单 entry=81592.5 / stop=81604.9），等同裸露仓位，被一个 tick 打掉。

### R7：逆势开空无门禁 → 单笔最大亏损
- 26 笔空单净 −5.21%（价格）。**2026-09-18 在 +5.22% 大阳线日逆势做空，单笔 −1.02%**（30 天最大亏损单）。
- 同期 AI 信号 312 次 BUY vs 2 次 SELL，做空路径（策略 SELL 高质量短 R/R 覆盖 AI-HOLD 等）
  系统性无视市场方向，"高 R/R"在急涨中恰恰是最危险的信号。

## 三、修复内容（已实现 + 测试）

### 代码
| 文件 | 修复 |
|---|---|
| `core/adaptive_bot.py` | R1 全仓止盈默认保持原目标；R2 手续费感知收紧门槛；R3 notional 走 ctVal；R4 按账户容量决策张数；R5 止盈单上下文入审计 |
| `core/adaptive_stop_loss.py` | R6 重试保留原风险距离，仅价格越界时夹到 current±裕度 |
| `core/position_close_audit.py` | R5 止损无成交时查止盈单 algo 历史，按止盈成交价确认 PnL；止损价缺失时回退止盈价估算 |
| `core/decision_engine.py` | R7 逆势做空门禁（24h 涨幅 > 上限禁止新开空） |
| `config/models.py` | 新增 `take_profit_full_amount_pull_ratio` / `taker_fee_rate` / `short_entry_max_daily_change` 三个配置项 + 校验 + from_env |

### 配置（`.env` / `.env.example`）
```

```

## 四、修复后的期望变化（保守估计）

假设修复后净止盈距离 ≈ 止损距离（0.62%，不再砍半且 R/R≥1）：

| 指标 | 修复前 | 修复后（估计） |
|---|---|---|
| 净盈利/笔 | +0.287% | +0.520% |
| 净亏损/笔 | −0.724% | −0.724% |
| 净盈亏比 | 0.396 | **0.718** |
| 盈亏平衡所需胜率 | 71.6% | **58.2%** |

盈亏平衡胜率从 71.6% 降到 58.2%。**但这仍高于常见的信号胜率**——本修复保证的是
"不再被出场结构稳定抽血"，不保证盈利。要真正转正，还需要（超出本次结构修复范围）：

1. **提高信号胜率**：当前 AI 融合 + 策略覆盖链路胜率低，建议用 `scripts/analyze_logs.py`
   持续监控，并考虑降低交易频率（只保留高置信、顺势信号）。
2. **仓位放大**：R4 修复后张数随账户容量决策。在策略被验证为正期望之前**不要放大仓位**——
   当前最小张数（≈$7.5 名义）反而是天然的风险隔离。
3. **先回测/纸面验证**：建议 `TEST_MODE=true` 跑 2~4 周，确认净盈亏比与胜率向盈亏平衡线收敛后再实盘。
