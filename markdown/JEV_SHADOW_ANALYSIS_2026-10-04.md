## 二、三分支假设验证

### 分支 2「Jev 清晰符合入仓 → 直接买」：0 次触发（死分支）

- 8 天 ~950 次 Jev 决策中，**buy 置信度峰值仅 0.67**（10/02 01:43，buy 概率 0.76），sell/short 峰值 0.25/0.30，**从未达到 0.75 直接采用线**。
- 10/02 01:32–01:43 的两次 buy(0.65/0.67) 出现在真实突破段（40 分钟 84.4k→85.0k，日内高点 86.9k），方向上是对的；但 LLM 同期 hold(55–63%)，系统全程空仓，错过了当日的 +2% 波段。
- 结论：**Jev 在现有输入（state 快照 + 单问题集）下，不具备"清晰看多"的表达能力**。它是否决门，不是买家。0.75 阈值保留无副作用；降到 0.65 会开始触发（每周 2–3 次），但那 47 次低置信 buy 没有结果数据背书（LLM 全部拒绝），不建议现在降。

### 分支 1「Jev 清晰不符合入仓 → 直接结束」：否决本身安全，但"直接结束"不建议

**否决质量（安全面）**：
- Jev hold≥0.50 的 191 个周期，LLM 实际判定 191/191 全部 hold，**一致率 100%，零分歧**。
- 8 天窗口内从未出现"Jev 高置信 hold 而 LLM 想 buy"的案例。Jev 的否决从未错杀过 LLM 的买入信号（LLM 本身不买）。

**交互成本（风险面，关键发现）**：
- ⚠️ **隐藏机制**：Jev adopted 的 hold 会把 Jev 的置信度（0.50–1.00）作为 `original_confidence` 传入 integrator，触发 **55% 翻转守卫**（`integrator.py`：AI 明确 HOLD ≥55% 时禁止技术层翻转 hold→BUY；该守卫是 9/13 亏损案例的教训）。
- on 期实测（10/01 00:00–12:01，75 周期）：技术层 can_buy=True 共 20 次，**20/20 全部被翻转守卫阻止**，其中 **9 次由 Jev 的 96–99% hold 触发**，11 次由 LLM 55–62% hold 触发。
- 两种设计对 8 天 5 个 BUY 机会的代价对比：
  - "直接结束"（用户原案，跳过全部下游）：错过 **2/5 = 40%**（10/03 13:43 Jev hold=0.53、19:01 Jev hold=0.90）
  - 现行"adopt 后仍走 integrator"：只错过 **1/5 = 20%**（19:01，0.90 ≥ 0.55 被守卫拦截；13:43 的 0.53 < 0.55，adopt 后仍能被技术层翻转成 BUY）
- 结论：**Jev 当第一道门 = 保留，但语义是"adopt 后继续过风控/优化层"，不是"直接结束"**。现行代码已是这个语义，无需改动。

### 分支 3「不清晰 → 升级 LLM」：按设计工作

- 233 个升级周期，LLM 233 次 hold；其中 1 个（10/03 13:33，Jev hold 0.49 升级 → LLM hold 45% < 55%）被技术层翻转成 BUY。
- **本系统的实际"买家"是本地自适应买入层**（trend_confirmation / pullback_buy / oversold_rebound），8 天 5 个 BUY 全部出自这里；Jev 和 LLM 都没有独立产出过 BUY。

## 三、真正的瓶颈（按影响排序）

shadow 窗口完整漏斗：

```
426 周期
  → 自适应买入 can_buy=True: 75 (17.6%)
  → 被 AI-hold≥55% 翻转守卫阻止: 64 (85%)   ← LLM hold 55–65% 是主因，与 Jev 无关
  → 放行翻转: 11
  → 被 R/R 过滤等下游挡回 HOLD: 8 (例: R/R=0.96 < 1.0 最低线)
  → 最终 BUY: 3
  → 执行失败(余额 $7.30 < 最小一手所需 ~$277): 3
  → 成交: 0
```

1. **账户余额 $7.30（硬约束）**：5/5 BUY 全部取消。最小 0.01 合约需 ~$277 余额（余额×0.30×10x杠杆/价格），0.03 手需 ~$830。
2. **LLM 100% hold + 55% 翻转守卫**：shadow 窗口技术买入机会 85% 被 LLM 的 55–65% hold 挡住——这是低频的主因。注意该窗口 Jev 不在决策链上（shadow 永不采用），瓶颈与 Jev 路由无关。
3. **R/R / 高位过滤器**：放行的 11 次翻转中 8 次被挡回（R/R 不足 1.0 等）。
4. **Jev 否决（次要放大器）**：on 模式实测 9/20（45%）的技术机会被 Jev 高置信 hold 拦截（上限估计；那 9 次均为震荡市，买点好坏无结果数据可回溯）。
5. **LLM 可靠性**：本窗口 0 次失败；9/28 的 qwen38 503（42 周期作废）为孤立事件，但无兜底 provider 仍是风险点。

## 四、结论与建议

**假设判定：三段式路由的架构方向合理，且现有实现（adopt → 继续走 integrator）已经等价于它。需要修正两点：**

1. "Jev 清晰不符合 → **直接结束**" 应改为 "**adopt 后继续走风控层**"（= 现状）。直接结束会多丢 40% 的技术层买入机会（2/5 vs 1/5）。
2. "Jev 清晰符合 → 直接买" 是死分支（8 天峰值 0.67），保留 0.75 阈值即可，Jev 定位为**快速否决门 + 延迟/成本节省**（on 模式可跳过 ~45% 周期的 LLM 调用，每周期省 5–9 秒 + API 成本），买入决策权留在 LLM + 本地技术层。
